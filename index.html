MODULE 1 — What is SQL?

SQL stands for Structured Query Language. It's the language you use to talk to a relational database.

Think of a database as a collection of Excel sheets (called tables), all linked to each other. SQL lets you ask questions like:

  • "Show me all students from Mumbai"
  • "What's the average CGPA of the 2024 batch?"
  • "Which students enrolled in Business Analytics and scored A?"

Where is SQL used?

  • Every app you use — Swiggy, Zomato, LinkedIn — stores data in databases
  • Business analytics, finance dashboards, reporting
  • Data science pipelines
  • As an MBA grad, SQL is one of the most in-demand skills for analytics, consulting, and product roles

MODULE 2 — The SELECT Statement

SELECT is the most fundamental SQL command. It retrieves data from a table.

Syntax:

SELECT column1, column2 FROM table_name;

Example 1 — Get specific columns:

SELECT name, city FROM students;

Returns: just the name and city columns from students.

Example 2 — Get everything:

SELECT * FROM students;

The * means "all columns." Use sparingly in real work — fetching unnecessary columns wastes resources.

Example 3 — Aliases (rename columns in output):

SELECT name AS student_name, cgpa AS score FROM students;

AS gives a column a temporary display name. Useful for cleaner reports.

Example 4 — Expressions in SELECT:

SELECT name, fees_paid / 1000 AS fees_in_thousands FROM students;

You can do math directly inside SELECT.

MODULE 3 — WHERE (Filtering Rows)

WHERE filters which rows come back. Think of it as applying a condition.

Syntax:

SELECT columns FROM table WHERE condition;

Comparison operators:

OperatorMeaning
=Equal to
!= or <>Not equal to
>, <Greater/less than
>=, <=Greater/less than or equal

Example 1 — Students from Mumbai:

SELECT name, city FROM students WHERE city = 'Mumbai';

Example 2 — Students with CGPA above 8:

SELECT name, cgpa FROM students WHERE cgpa > 8.0;

Example 3 — Combining conditions with AND / OR:

-- Both must be true
SELECT name FROM students WHERE city = 'Mumbai' AND cgpa > 8.0;

-- At least one must be true
SELECT name FROM students WHERE city = 'Mumbai' OR city = 'Delhi';

Example 4 — NOT:

SELECT name FROM students WHERE NOT city = 'Mumbai';
-- same as: WHERE city != 'Mumbai'

Example 5 — IN (shortcut for multiple OR conditions):

SELECT name FROM students WHERE city IN ('Mumbai', 'Delhi', 'Pune');

Much cleaner than writing three OR conditions.

Example 6 — BETWEEN:

SELECT name, cgpa FROM students WHERE cgpa BETWEEN 7.5 AND 8.5;

BETWEEN is inclusive on both ends.

Example 7 — LIKE (pattern matching):

SELECT name FROM students WHERE name LIKE 'A%';
-- Returns names starting with A: Ananya

SELECT name FROM students WHERE name LIKE '%an%';
-- Returns names containing 'an': Siddhant, Ananya, Karan

% = any number of characters. _ = exactly one character.

Example 8 — NULL values:

SELECT name FROM students WHERE fees_paid IS NULL;
SELECT name FROM students WHERE fees_paid IS NOT NULL;

Never use = NULL. Always use IS NULL. This is a very common beginner mistake.

MODULE 4 — ORDER BY (Sorting)

ORDER BY sorts your results.

SELECT name, cgpa FROM students ORDER BY cgpa DESC;
-- DESC = highest first. ASC = lowest first (default)

Multi-level sort:

SELECT name, city, cgpa FROM students
ORDER BY city ASC, cgpa DESC;
-- First sorts by city A-Z, then within same city sorts by CGPA high-to-low

MODULE 5 — LIMIT (Control Row Count)

SELECT name, cgpa FROM students ORDER BY cgpa DESC LIMIT 3;
-- Top 3 students by CGPA

Use case: leaderboards, top-N reports, pagination.

MODULE 6 — Aggregate Functions

These collapse many rows into a single summary number.

FunctionDoes What
COUNT()Counts rows
SUM()Adds up values
AVG()Calculates average
MAX()Highest value
MIN()Lowest value

Examples:

SELECT COUNT(*) FROM students;
-- Total number of students: 5

SELECT AVG(cgpa) FROM students;
-- Average CGPA across all students

SELECT MAX(cgpa), MIN(cgpa) FROM students;
-- Highest and lowest CGPA

SELECT SUM(fees_paid) FROM students;
-- Total fees collected

SELECT COUNT(DISTINCT city) FROM students;
-- How many unique cities students come from

MODULE 7 — GROUP BY

GROUP BY splits rows into groups and applies aggregates to each group. This is where SQL gets really powerful for business analysis.

Syntax:

SELECT column, AGGREGATE(other_column)
FROM table
GROUP BY column;

Example 1 — Average CGPA per batch:

SELECT batch, AVG(cgpa) AS avg_cgpa
FROM students
GROUP BY batch;

Result:

batchavg_cgpa
20247.8
20258.65

Example 2 — Students per city:

SELECT city, COUNT(*) AS student_count
FROM students
GROUP BY city;

Example 3 — Total fees collected per batch:

SELECT batch, SUM(fees_paid) AS total_fees
FROM students
GROUP BY batch;

HAVING — Filtering groups (not rows):

WHERE filters individual rows before grouping. HAVING filters groups after grouping.

-- Batches where average CGPA is above 8
SELECT batch, AVG(cgpa) AS avg_cgpa
FROM students
GROUP BY batch
HAVING AVG(cgpa) > 8;

Order of clauses (important to memorize):

SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

MODULE 8 — JOINs

This is the most important concept in SQL. Real databases have data spread across multiple tables. JOINs combine them.

Think of it this way: students has student info, enrollments has which courses they took. To answer "what courses did Siddhant take?" you need both tables.

INNER JOIN

Returns only rows that have a match in both tables.

SELECT students.name, enrollments.course_id, enrollments.grade
FROM students
INNER JOIN enrollments ON students.student_id = enrollments.student_id;

This connects the two tables via the shared student_id column. Any student with no enrollments won't appear.

With aliases (cleaner syntax):

SELECT s.name, e.course_id, e.grade
FROM students s
INNER JOIN enrollments e ON s.student_id = e.student_id;

Three-table join:

SELECT s.name, c.course_name, e.grade
FROM students s
INNER JOIN enrollments e ON s.student_id = e.student_id
INNER JOIN courses c ON e.course_id = c.course_id;

Now you get student name + actual course name + grade, all in one query.

LEFT JOIN

Returns all rows from the left table, and matching rows from the right. If no match, right side shows NULL.

SELECT s.name, e.course_id
FROM students s
LEFT JOIN enrollments e ON s.student_id = e.student_id;

Use case: "Show me all students, and if they've enrolled in anything, show that too." Students with no enrollments still appear, with NULL for course_id.

RIGHT JOIN

Opposite of LEFT JOIN — all rows from the right table, matches from left. Less commonly used; most people rewrite it as a LEFT JOIN.

FULL OUTER JOIN

Returns all rows from both tables. NULLs fill in where there's no match on either side.

SELECT s.name, e.course_id
FROM students s
FULL OUTER JOIN enrollments e ON s.student_id = e.student_id;

Visual summary:

INNER JOIN    = only the overlap
LEFT JOIN     = all of left + overlap
RIGHT JOIN    = all of right + overlap
FULL JOIN     = everything from both

MODULE 9 — Subqueries

A subquery is a query inside another query. The inner query runs first and its result is used by the outer query.

Example 1 — Students with above-average CGPA:

SELECT name, cgpa
FROM students
WHERE cgpa > (SELECT AVG(cgpa) FROM students);

The inner query calculates the average. The outer query filters against it.

Example 2 — Students enrolled in Business Analytics:

SELECT name FROM students
WHERE student_id IN (
    SELECT student_id FROM enrollments WHERE course_id = 'C01'
);

Example 3 — Subquery in FROM clause (derived table):

SELECT batch, avg_cgpa
FROM (
    SELECT batch, AVG(cgpa) AS avg_cgpa
    FROM students
    GROUP BY batch
) AS batch_summary
WHERE avg_cgpa > 8;

MODULE 10 — INSERT, UPDATE, DELETE

These are the write operations (as opposed to SELECT which is read-only).

INSERT — Add new rows

INSERT INTO students (student_id, name, batch, city, cgpa, fees_paid)
VALUES (6, 'Priya', 2025, 'Chennai', 8.4, 75000);

Insert multiple rows at once:

INSERT INTO students (student_id, name, batch, city, cgpa, fees_paid)
VALUES
  (7, 'Arjun', 2024, 'Bangalore', 7.5, 150000),
  (8, 'Neha', 2025, 'Jaipur', 8.8, 0);

UPDATE — Modify existing rows

UPDATE students
SET fees_paid = 150000
WHERE student_id = 3;
-- Rohan has now paid full fees

Always use WHERE with UPDATE. Without it, you update every single row.

-- Increase CGPA by 0.1 for all 2024 batch students
UPDATE students
SET cgpa = cgpa + 0.1
WHERE batch = 2024;

DELETE — Remove rows

DELETE FROM students WHERE student_id = 8;

Again, WHERE is critical. DELETE FROM students; with no WHERE deletes the entire table's data.

MODULE 11 — CREATE TABLE & Data Types

Data Types

TypeUse for
INTWhole numbers (1, 42, -7)
DECIMAL(p,s)Precise decimals — use for money, CGPA
VARCHAR(n)Variable-length text up to n chars
TEXTLong text with no fixed limit
DATEDates (2024-05-15)
DATETIMEDate + time
BOOLEANTrue/False

CREATE TABLE

CREATE TABLE students (
    student_id   INT PRIMARY KEY,
    name         VARCHAR(100) NOT NULL,
    batch        INT,
    city         VARCHAR(50),
    cgpa         DECIMAL(3,1),
    fees_paid    INT DEFAULT 0
);

Constraints:

  • PRIMARY KEY — uniquely identifies each row, cannot be NULL
  • NOT NULL — this column must always have a value
  • DEFAULT — fallback value if none is provided
  • UNIQUE — no two rows can have the same value in this column
  • FOREIGN KEY — links to a primary key in another table
CREATE TABLE enrollments (
    enrollment_id INT PRIMARY KEY,
    student_id    INT,
    course_id     VARCHAR(10),
    grade         VARCHAR(5),
    FOREIGN KEY (student_id) REFERENCES students(student_id)
);

ALTER TABLE — Modify an existing table

-- Add a column
ALTER TABLE students ADD COLUMN email VARCHAR(100);

-- Drop a column
ALTER TABLE students DROP COLUMN email;

-- Rename a column
ALTER TABLE students RENAME COLUMN cgpa TO gpa;

DROP TABLE — Delete the table entirely

DROP TABLE students;           -- Deletes table and all data
TRUNCATE TABLE students;       -- Deletes all data but keeps the table structure

MODULE 12 — CASE (Conditional Logic)

CASE lets you add if-else logic inside a query.

SELECT name, cgpa,
    CASE
        WHEN cgpa >= 9.0 THEN 'Distinction'
        WHEN cgpa >= 8.0 THEN 'First Class'
        WHEN cgpa >= 7.0 THEN 'Second Class'
        ELSE 'Pass'
    END AS grade_category
FROM students;

Use case: creating custom labels, bucketing values into ranges, building report categories.

MODULE 13 — String & Date Functions

String Functions

SELECT UPPER(name) FROM students;           -- SIDDHANT
SELECT LOWER(name) FROM students;           -- siddhant
SELECT LENGTH(name) FROM students;          -- 9
SELECT CONCAT(name, ' - ', city) FROM students;  -- Siddhant - Mumbai
SELECT TRIM('  hello  ');                   -- 'hello'
SELECT SUBSTRING(name, 1, 3) FROM students; -- Sid

Date Functions

SELECT CURRENT_DATE;                          -- today's date
SELECT YEAR(CURRENT_DATE);                    -- 2026
SELECT DATEDIFF('2026-05-01', '2024-05-01');  -- 731 days
SELECT DATE_FORMAT(CURRENT_DATE, '%d-%m-%Y'); -- 18-03-2026

MODULE 14 — Views & Indexes

Views — Saved queries you can treat like a table

CREATE VIEW high_performers AS
SELECT name, cgpa, city
FROM students
WHERE cgpa >= 8.5;

-- Now use it like a table:
SELECT * FROM high_performers;

Use case: simplify complex queries, create reusable data layers, control what data different users can see.

Indexes — Speed up queries

CREATE INDEX idx_city ON students(city);

Without an index, the database scans every row to find matches. An index is like a book's index — it jumps straight to the right page. Use on columns you filter or join on frequently.

Quick Reference: Full Query Structure

SELECT   column1, AGG(column2) AS alias     -- what to show
FROM     table1 t1                           -- main table
JOIN     table2 t2 ON t1.id = t2.id         -- bring in related data
WHERE    condition                           -- filter rows first
GROUP BY column1                            -- group for aggregation
HAVING   AGG(column2) > value               -- filter groups
ORDER BY column1 DESC                       -- sort results
LIMIT    10;                                -- cap the output
